# S3 Vectorsを保存先にしたBedrock Knowledge BasesのRAG

国土交通省「移住・二地域居住等促進専門委員会」第1〜3回（2023年）の議事要旨を検索し、検索原文と出典を確認してから、その内容を根拠に回答するサンプルです。

## 構成

- `terraform/`: 文書用S3、S3 Vectorsのベクトルバケットとインデックス、Knowledge Base、データソース、専用IAMロール。
- `scripts/`: 取り込み・検索・回答生成のクライアントと共通処理。
- `documents/`: 議事要旨3件と、会議番号・開催日・出典URLのメタデータ。
- `commands.sh`: 準備・デプロイ・同期・検索・回答生成・削除のコマンド。
- `SOURCES.md`: 資料の出典と加工内容。

Terraformは文書を通常のS3に配置します。同期時にKnowledge Basesが文書を分割・ベクトル化し、S3 Vectorsに登録します。PythonはRetrieveで検索し、取得した原文をConverseに渡して回答を生成します。

埋め込みはTitan Text Embeddings V2（`amazon.titan-embed-text-v2:0`）、1024次元のfloat32です。インデックスの距離尺度はcosine、チャンクは500トークン・重複15%としています。検索方式は `SEMANTIC` です。

## 準備と実行

Python 3.14、uv、Terraform 1.12以上2.0未満、AWS CLIを使用します。AWSプロバイダーは6.66.0に固定しています。プロファイル・リージョン・回答モデルは `terraform/variables.tf` にまとめ、既定は `develop`、`ap-northeast-1`、`jp.anthropic.claude-sonnet-4-6` です。

このディレクトリで `commands.sh` の必要なコマンドを順に実行し、各処理の成功を確認してから次へ進みます。WindowsではGit Bashを利用し、uvとTerraformがPATHから見つかる状態にします。

実行者にはリソースの作成・PassRole、取り込みジョブの開始・取得、検索、回答モデル呼び出しの権限が必要です。KB用の専用IAMロールには対象S3の読み取り、Titanの呼び出し、対象インデックスの操作を許可します。回答モデルはローカル実行者の権限で呼び出します。

Terraformによるデプロイ後、`sync` で取り込みます。最大900秒待ち、完了かつ失敗文書0件を成功とします。タイムアウトしてもAWS側のジョブは続いている場合があります。文書更新時も、S3への反映と同期を順に行ってください。

## 検索と回答の確認

`retrieve` は検索原文・資料ID・会議番号・開催日・出典URL・スコアを表示します。`ask` は同じ表示を行った後、その検索結果をClaudeに渡して回答を表示します。検索結果と回答、生レスポンスは `results/` に保存します。

既定の質問は「空き家があるのに、二地域居住向けの賃貸物件が少ないのはなぜだと議論されていますか？」です。`--meeting` で第1〜3回のいずれかに絞り込み、`--top-k` で取得件数を1〜20件（既定5件）に変更できます。会議番号による絞り込みは検索条件です。

回答内の `[R1]` などを、同じ実行で表示された検索原文と照合してください。スコアは正解確率ではなく、資料IDが付いていても引用の正しさは保証されません。資料は2023年の議論なので、現在の制度や決定事項と混同しないよう確認します。

文書に質問と回答が書かれていても、別々のチャンクに分かれて片方だけが検索される場合があります。回答が不十分なときは、検索原文に必要な根拠が含まれるかを確認し、取得件数や会議の絞り込みを変えて比較します。

## 後片付け

同期・質問処理の終了後、`commands.sh` 末尾の削除用コマンドを実行します。取り込みデータ、KB、S3 Vectorsのインデックスとベクトルバケット、文書用S3、専用IAMロールを削除します。文書用S3に追加したオブジェクトも削除対象です。ローカルの文書と実行結果は残ります。
